# 验证记录

## 0.5.6

开发环境为 Windows 11、CPU 推理、最多 4 个计算线程；与 0.5.5 使用相同的 10 个本地模型。

- 自动回归：652 项通过、1 项跳过；跳过项仍为 POSIX 权限检查。Ruff 与核心类型检查通过。
- 两组各 8 张合成办公页，覆盖清晰、小字、失焦、运动模糊、淡字、阴影噪声、JPEG 压缩及淡字叠加模糊。共 2,168 个参考字符，普通文字模式字符错误由 406 降至 3。第二组文字未用于调整增强参数。
- 版面模式对第一组 8 张图片复测，字符错误由 261 降至 1；标题、正文、表格等仍沿用原版面引擎。
- 改善集中在淡字、阴影低对比度和淡字模糊场景。清晰、小字、普通失焦、运动模糊及 JPEG 样本未退步；小字、失焦与 JPEG 各仍有字符错误。
- 13 张用户授权本地图片的处理结果与 0.5.5 逐字节一致。既有漏行目标页真实识别通过：指定内容各出现一次，加密项目往返和导出通过，原图未变。
- 增强不增加模型或整页推理次数；只对符合条件的亮色低对比度文本图片调整像素亮度。不对识别文字执行推测补全，不自动替换人工校对内容。
- 完整源码导出默认校验并附带全部模型，流式写入 ZIP，避免将全部模型同时读入内存。仓库上传目录可通过 `--code-only` 单独导出。

这些是有意构造的退化样本，错误率不能代表真实文件总体准确率。强锐化在部分失焦样本上增加误识别，未作为新的默认处理启用。严重失焦、遮挡及缺失笔画仍需人工复核。

复现命令：

```powershell
python -B -m tools.benchmark_degraded_ocr --output validation/degraded --models models
python -B -m tools.benchmark_degraded_ocr --output validation/holdout --models models --holdout
python -B -m tools.benchmark_degraded_ocr --output validation/layout --models models --layout
```

对比时使用同一工具、字体与输入参数，分别加载两个版本的应用源码。公开合成样本可保留；真实资料与识别正文不得提交到仓库。产物哈希、打包后识别及原生启动结果随交付报告记录。八代酷睿、8GB 内存与 GitHub 托管工作流未在本轮重新实测。

## 0.5.5

本版修复更新日志版本切换，统一产品文案，并整理公开源码。

开发环境：Windows 11 x64，Python 3.12.10，PySide6 6.8.3。

- 源码自动回归：641 项通过、1 项跳过，44.50 秒；跳过项为 POSIX 权限检查。
- 原生版本窗口：深色、浅色各切换 9 个版本，确认版本号、标题和日志正文同步更新；键盘选择与关闭返回设置通过。
- Ruff 与核心类型检查通过；公开 CHANGELOG 与应用内日志一致。
- 公开源码目录独立测试及逐文件 SHA-256 核对结果记录于交付报告。

模型、识别与导出算法沿用 0.5.4，界面文案变化不构成准确率或速度提升证据。

GitHub 工作流提供自动源码检查。工作流未在托管环境运行前，不标记为 GitHub 验证通过。目标八代酷睿电脑、8GB 内存、Windows 10 与 WPS 仍须分别实测。
